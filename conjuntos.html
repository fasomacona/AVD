1.1 Conjunto de Datos

Las tres grandes características que definen los datos en la actualidad: Volumen, Variedad y Velocidad.

¿Qué es un Conjunto de Datos?

Un conjunto de datos (dataset) es una colección estructurada o no estructurada de información que representa observaciones, hechos o mediciones sobre un fenómeno o dominio particular. Puede estar organizado en tablas (filas = observaciones, columnas = variables), documentos, imágenes, series temporales, grafos, etc.

En el contexto de la ciencia de datos moderna, especialmente con el auge del Big Data, los conjuntos de datos se caracterizan por tres propiedades fundamentales conocidas como las 3 Vs:

Volumen

Cantidad masiva de datos generados y almacenados.

Variedad

Diversidad de formatos, tipos y fuentes de datos.

Velocidad

Rapidez con la que se generan y deben procesarse los datos.

1.1.1 Datos de Alto Volumen

El volumen se refiere a la cantidad de datos que se generan, almacenan y procesan. En la actualidad, hablamos de terabytes, petabytes e incluso exabytes de información.

Ejemplos reales de alto volumen

  • Redes sociales: Facebook genera más de 4 petabytes de datos al día.
  • IoT (Internet de las Cosas): Sensores industriales y dispositivos conectados producen flujos continuos de lecturas.
  • Comercio electrónico: Amazon procesa millones de transacciones y clics diarios.
  • Genómica: Una sola secuencia completa del genoma humano puede ocupar varios gigabytes.
Implicación para el análisis: Los métodos tradicionales de almacenamiento y procesamiento (como cargar todo en memoria RAM) dejan de ser viables. Se requieren tecnologías como Hadoop, Spark, bases de datos distribuidas y técnicas de muestreo inteligente.

Desafíos del alto volumen

Desafío Descripción Estrategia de mitigación
Almacenamiento Costos y capacidad limitada Almacenamiento distribuido (HDFS, S3), compresión
Procesamiento Tiempo de cómputo excesivo Procesamiento paralelo, MapReduce, Spark
Transferencia Ancho de banda y latencia Procesamiento cerca de los datos (edge computing)
Calidad Más datos ≠ mejores datos Limpieza, filtrado y validación rigurosa

1.1.2 Datos de Alta Variedad

La variedad se refiere a la diversidad de formatos, estructuras y fuentes de los datos. No todos los datos vienen en neat tables de Excel o CSV.

Clasificación de datos según su estructura

Estructurados

Datos organizados en esquemas fijos (tablas relacionales).

  • Bases de datos SQL
  • Hojas de cálculo
  • CSV, TSV
Semi-estructurados

Tienen alguna organización, pero no un esquema rígido.

  • JSON, XML
  • Logs de servidores
  • Emails
No estructurados

Sin formato predefinido o esquema.

  • Texto libre, documentos
  • Imágenes, video, audio
  • Redes sociales (posts)
Ejemplo práctico: Un sistema de recomendación de una tienda en línea puede combinar:
  • Datos estructurados: historial de compras (tabla relacional)
  • Semi-estructurados: clics y eventos de navegación (JSON)
  • No estructurados: reseñas de productos (texto libre) e imágenes de productos

Implicaciones de la variedad

La variedad obliga a utilizar herramientas flexibles de extracción y transformación (ETL/ELT), parsers específicos, técnicas de NLP para texto, visión por computadora para imágenes, y modelos de datos que permitan integrar fuentes heterogéneas (por ejemplo, data lakes).

1.1.3 Datos de Alta Velocidad

La velocidad se refiere a la tasa a la que se generan, transmiten y deben procesarse los datos. En muchos escenarios, el valor de la información disminuye rápidamente con el tiempo (datos en tiempo real o near-real-time).

Tipos de velocidad de datos

  • Batch (por lotes): Procesamiento periódico (diario, semanal). Ejemplo: reportes mensuales de ventas.
  • Near real-time: Procesamiento con latencia de segundos o minutos. Ejemplo: actualización de inventario.
  • Real-time / Streaming: Procesamiento continuo y casi instantáneo. Ejemplo: detección de fraude en tarjetas de crédito, monitoreo de sensores industriales.
Tecnologías clave para alta velocidad:
  • Apache Kafka, Apache Flink, Spark Streaming
  • Bases de datos en memoria (Redis)
  • Arquitecturas Lambda y Kappa
  • Edge computing (procesar cerca de la fuente)

Ejemplo ilustrativo

Un sistema de monitoreo de tráfico vehicular recibe datos de cámaras y sensores cada segundo. Si se procesan solo al final del día (batch), se pierde la capacidad de reaccionar a congestiones en tiempo real. Con procesamiento en streaming se pueden ajustar semáforos dinámicamente.

Resumen de las 3 Vs

Característica Pregunta clave Impacto en el preprocesamiento
Volumen ¿Cuántos datos hay? Necesidad de muestreo, procesamiento distribuido, reducción de dimensionalidad
Variedad ¿Qué tipos y formatos? Parsers múltiples, normalización de esquemas, técnicas de unificación
Velocidad ¿A qué velocidad llegan? Pipelines de streaming, ventanas temporales, procesamiento incremental

Estas tres dimensiones no son independientes: un sistema de IoT industrial puede generar alto volumen de datos de alta variedad (sensores, logs, imágenes) a alta velocidad. El preprocesamiento debe diseñarse considerando las tres simultáneamente.
